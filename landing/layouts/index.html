01 / THE IDEA

Separate the logic.
Keep the pipeline.

CI YAML is the destination, not the place you have to write your shell scripts. Build a source tree that your editor and local tools understand.

01 / SOURCE
{ }

Write a script

Put Bash in a .sh file, with normal syntax highlighting, linting, and tests.

02 / REFERENCE
↗

Point YAML to it

Use a script path in your source pipeline YAML. Keep the configuration readable.

03 / COMPILE
⇄

Generate the output

Run the compiler to inline scripts into the final CI YAML before deployment.

02 / A SHORT WALKTHROUGH

From files to
final config.

Start with an existing pipeline or initialize a new project. Edit scripts as source files, then compile into your output directory.

Follow the full quick start ↗
pipeline-workflow.sh
# Set up a source project
bash2yaml init

# Or extract scripts from existing YAML
bash2yaml decompile --in-file .gitlab-ci.yml \
  --out my-project/

# Compile without running the pipeline
bash2yaml compile --in my-project/ \
  --out compiled/
